网页代码生成规范

2026-09-15 00:00

给 D 老师写代码的规范（修订版 v2）

一、交付形式

1. 默认交付 … 标记块，不是整页 HTML。只有加加明确说「要整页 html 代码」时才给完整 单文件。

2. 不拆文件，CSS 和 JS 全部内联在标记块里。

3. 不引入任何外部依赖：不用 CDN，不引外部字体、图片、图标库。

4. 所有图标、装饰、人物、气泡、卡片，全部用 CSS 或 SVG 手绘。

5. 网页代码里不用 emoji。聊天气泡、日记卡片里加加自己允许的符号保留，不在此限。

6. 代码要能直接复制粘贴，保存成 .html 后双击就能用。

7. 禁止把可视代码和长正文混在一起。工具页就是工具页，文章就是文章。

8. 所有对外链接一律 target="_blank" 加 rel="noopener noreferrer"。

二、兼容要求

1. 必须能跑在 GitHub Pages 上，纯静态。

2. 不接后端，不发请求，不用 fetch 调外部接口。

3. 路径一律用相对路径，禁止用 /xxx 这种从根目录开始的绝对路径。

4. 部署到站上的文件名只用英文小写、数字、连字符。文件名格式：工具名-YYYYMMDD.html。例：bubble-20260915.html。

5. 适配手机和电脑，宽度不超过 100%，不出现横向滚动条。

6. 中文 slug 先转拼音或哈希，不允许中文直接当文件名。

三、代码质量

1. 不能有会报错的语法，不能留半截代码。

2. 不能用 alert、confirm 这种打断式提示，需要提示就用页面内的元素。

3. 动画要轻，不要一开页面就满屏乱动。

4. 颜色统一，不要一个页面七八种不搭的颜色。

5. 所有可点元素必须有 hover 或点击反馈。

6. 交互状态必须可逆。点击能开就得能关，不要把用户锁在只能前进不能后退的状态里。

7. 页面需要多个模式时用一个变量控制，不写多套重复代码。

8. 非必要不用 requestAnimationFrame。若使用，必须能在页面失焦或组件关闭时主动 cancel。

9. 不写自动播放音频，不写自动请求用户权限。

10. 如使用 localStorage 保存设置，必须用注释说明存的是什么、什么时候清。禁止存密码、账号、隐私文本。

11. 关键改动点加中文注释。颜色变量、文字内容、尺寸参数单独抽出来放在文件顶部，方便加加直接改。

12. 上传前必须自测：手机宽度、刷新后状态、点击能不能回退、控制台有没有报错。

四、给加加的场合

1. 她要的是能玩、能点、能看的页面，不是给她贴代码块。

2. 写完代码后面附一句「保存成什么名字、怎么打开」。

3. 她只是要贴到站里当文章时，不要给整页 HTML，给她 Markdown 能直接放的内容。

4. 她要贴进站里当小工具时，必须按站点结构给：单独一个 .html 放 tools/ 或 playground/，文章里只放链接。

5. 涉及路径时先确认站点文章页面的深度，再决定 ../ 还是 ../../。

6. 涉及中文 slug 时先转拼音或哈希，不允许中文直接当文件名。

7. 提取或注入 HTML 时，遇到 、<!-- 这类会截断的字符串，必须先转义。

8. 改完代码要告诉加加：这个能不能直接用，还是得让 Trae 整合。

五、我们两个写代码的区别（给加加留的）

1. D 老师写代码偏直给，先给能跑的，再解释。

2. 江予朔偏稳，先讲结构，再给代码。

3. 两人都不装懂，不会就说不会，不能硬编。

4. 两人都不替加加做决定，她让改哪就改哪。

六、禁止

1. 禁止写一半停下来问「要不要继续」。

2. 禁止在代码里留占位符说「这里自己填」。

3. 禁止把上一版没跑通的代码换皮给她。

4. 禁止给多套方案让她选，除非她主动要对比。

5. 禁止在代码里夹私货，写和需求无关的内容。

七、江予朔补充

1. 禁止把可视代码和长正文混在一起。工具页就是工具页，文章就是文章。

2. 交互状态必须可逆。点击能开，就得能关。

3. 所有对外链接一律 target="_blank" 加 rel="noopener noreferrer"。

4. 如使用 localStorage 保存设置，必须用注释说明存的是什么、什么时候清。禁止存密码、账号、隐私文本。

5. 非必要不用 requestAnimationFrame。若使用，必须能在页面失焦或组件关闭时主动 cancel。

6. 不写自动播放音频，不写自动请求用户权限。

7. 关键改动点要加中文注释。颜色变量、文字内容、尺寸参数单独抽出来放在文件顶部。

8. 文件名统一为：工具名-YYYYMMDD.html。

9. 页面需要多个模式时用一个变量控制，不写三套重复代码。

10. 上传前必须自测：手机宽度、刷新后状态、点击能不能回退、控制台有没有报错。

八、Pages CMS / playable 专项（新增，每次写代码必须遵守）

背景： 加加的站点用 Pages CMS 编辑文章，CMS 会自动处理文本，历史上踩过几个固定的坑。写代码时按下面的规则防守，就不会再出问题。

8.1 JS 属性访问一律用方括号写法

原因： Pages CMS 会把 JS 代码里的 xxx.yyy 自动链接化成 [xxx]([http://xxx)，导致]([http://xxx)，导致](http://xxx)，导致)) 语法崩溃、事件绑定不执行、按钮点不动。

规则： JS 里所有「对象.属性」都写成「对象['属性']」。

· Math.random() → Math['random']()

· document.getElementById() → document['getElementById']()

· element.classList.add() → element['classList']['add']()

· [e.target](http://e.target) → e['target']

· window.setTimeout → window['setTimeout']

· arr.length → arr['length']

· str.indexOf() → str['indexOf']()

例外： 对象字面量里的 key: value 不用改，因为 key 后面跟的是冒号不是点。

例外： CSS 和 HTML 不受影响，正常写。

例外： 自己定义的对象属性读取也尽量走方括号，比如 card['name']、item['reversed']。

8.2 样式必须锁在根类里，不能污染文章页

原因： 之前用过 html, body, * { ... } 全局选择器，把整篇文章版式搞乱了。

规则：

· 所有样式选择器必须以根类开头，例如 .tarot-app .t-title { ... }

· 不能用 html、body、*、a、button、input 等裸标签选择器

· 不能改 font-size 的全局基准

· box-sizing 也只能作用于根类内：.xxx, .xxx *, .xxx* ::before, .xxx *::after { box-sizing: border-box; }

8.3 类名和 id 加前缀，避免和站点撞车

规则：

· 根类用工具名英文：.tarot-app、.macaron-snake

· 内部类名加短前缀：.t-title、.ms-chip

· id 也加前缀：id="t-start"、id="ms-board"

· 不要用 container、wrapper、header、main 这种通用名

8.4 根类内的子元素要锁住 flex 尺寸

原因： 站点布局可能是 flex，会把子元素压扁或拉长。

规则：

· 根类内直接子元素加 flex: 0 0 auto，防止被站点 flex 布局拉伸

· 有明确尺寸的元素（棋盘、卡片）写死宽高，不用百分比

· 不要用 height: 100% 依赖父元素

8.5 尺寸参数用 CSS 变量，写死像素，不用百分比撑高

原因： 踩过 padding-top: 165% 的坑 —— 这个百分比是相对父容器宽度算的，牌宽被 max-width 限制了，但高度按整个牌桌宽度算，结果被拉成长条。

规则：

· 需要固定宽高比的元素（牌、卡片、头像），写死像素宽高，不用百分比撑高

· 尺寸参数抽成 CSS 变量放在根类顶部：--t-card-w: 150px; --t-card-h: 248px;

· 小屏媒体查询里整体缩一档：@media (max-width: 420px) { --t-card-w: 132px; ... }

· 不用 aspect-ratio（兼容性不稳）

8.6 JS 绑定事件要有重试机制

原因： playable 系统可能把 抽出来提前执行，此时 DOM 还没生成，getElementById 拿到 null，事件绑定直接崩。

规则：

· DOM 引用和事件绑定全部包在 init() 函数里

· init() 里检查关键元素是否齐全，缺一个就返回 false

· 外层写重试：每 100ms 试一次，最多 40 次（4 秒）

· document.readyState === 'loading' 时挂 DOMContentLoaded，否则直接 tryInit()


function tryInit() {

  if (init()) return;

  tries++;

  if (tries < MAX_TRIES) window['setTimeout'](tryInit, 100);

}

if (document['readyState'] === 'loading') {

  document['addEventListener']('DOMContentLoaded', tryInit);

} else {

  tryInit();

}

8.7 移动端防双击缩放

原因： 移动端快速双击按钮会触发浏览器缩放，看起来像「点到放大页面」。

规则：

· 按钮加 touch-action: manipulation

· 按钮加 -webkit-tap-highlight-color: transparent 去掉点击蓝框

· 如果站点模板允许，viewport 加 maximum-scale=1.0, user-scalable=no（这条由站点模板统一处理，代码里不用重复写）

8.8 交付前自检清单

每次给代码前，自己过一遍：

□ JS 里没有 xxx.yyy 形式（除对象字面量和注释）

□ 所有样式选择器以根类开头

□ 类名、id 都带前缀

□ 根类内子元素有 flex: 0 0 auto

□ 固定尺寸元素用像素，不用百分比撑高

□ init() 有重试机制

□ 按钮有 touch-action: manipulation

□ 交互可逆（能开能关、能重置）

□ 没有 alert / confirm / 自动播放 / 自动请求权限

□ 颜色、文案、尺寸抽在顶部方便改

□ 没有 emoji

□ 交付形式是 块

8.9 出问题时的排查顺序

1. 看控制台有没有报错，报错行号直接定位

2. 搜索代码里有没有 [xxx]([http://xxx](http://xxx)) 这种被 CMS 改坏的痕迹

3. 检查事件绑定是否在 DOM 就绪后才执行

4. 检查尺寸是不是被父容器拉伸（用浏览器开发者工具看盒模型）

5. 如果实机问题定位不了，让加加把 Trae 修好的版本发来对比，不瞎猜

8.10 不装懂原则

· 如果这套 playable 系统的具体渲染机制不清楚，不猜，先要实机报错信息或对比版本

· 连续两次猜错方向，停手，让加加找 Trae 或者发报错截图

· 宁可说「我需要看报错」，也不浪费加加的时间
